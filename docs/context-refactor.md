# Graffiti Ghosts — Refactored Project Context

## Purpose

This document is the operational index for the refactored Graffiti Ghosts context, combining the current game-design source of truth with the reusable methods extracted from the user-provided research report.[DR-1]

The project remains a short-session stealth platformer in urban fantasy, with magical graffiti, ghost replay, raid scoring, hideout progression, Android support, and Flutter Web/WasmGC delivery as documented by the existing project specifications.[GG-1]

The research report is adopted as a **process and governance reference**, while its generic Shipaton examples, sample puzzle loop, sample currencies, sample prices, ads, subscriptions, package list, and RevenueCat products remain non-binding until explicitly approved.[DR-1]

## Mandatory feature contract

Every new mechanic must document player intent, input, state, transition, feedback, reward, failure, recovery, tuning variables, accessibility alternatives, platform impact, tests, and traceability links before implementation.[DR-1] [GG-2]

## Gates

No implementation begins when a required upstream answer is unknown, ambiguous, conflicting, or only implied by a generic example.[DR-1]

A change is merge-ready only when focused tests, regression tests, static analysis, relevant Android/Web/Wasm builds, accessibility checks, performance evidence, and documentation updates pass.[GG-2]
