# Graffiti Ghosts

Graffiti Ghosts is a single-player stealth platformer for Android and Web/Wasm. Each raid is designed to take less than three minutes: observe a pre-built urban-fantasy fortress, use acrobatic movement and magical graffiti, escape pursuit through alternative routes, steal treasure, and compare the run against a recorded ghost.

## MVP scope

The first vertical slice includes jump/acrobatic movement, wall-grab, slide, magical graffiti that reveals routes and creates temporary shortcuts, chase-and-escape flow, ghost comparison, score weighting of 40% time, 40% treasure, and 20% failures, plus a visible result panel. Monetization is out of the executable MVP path; the design boundary remains cosmetic purchases and optional ads that do not increase competitive score.

## Engineering constraints

The MVP uses only the Dart SDK and Flutter SDK. Domain and application code must not import Android, Web, Wasm, Flutter UI, or third-party SDKs. Platform adapters belong under infrastructure. The intended architecture is Clean Architecture with Ports & Adapters, SOLID, Clean Code, Object Calisthenics, Test-Driven Development, and Spec-Driven Development.

## Local commands

```bash
flutter pub get
flutter analyze
flutter test
flutter build web --wasm
flutter build apk --release
```

Flutter is installed by CI, so contributors without a local Flutter SDK can still open pull requests and rely on the validation workflow.

## Branching and commits

Use `main` for releasable code, `develop` for integration, and short-lived `feature/*`, `fix/*`, `refactor/*`, `test/*`, `docs/*`, and `chore/*` branches. Commit messages follow Conventional Commits, for example `feat(raid): add alternative escape route` or `fix(score): clamp failure penalty`.

Every pull request must reference an Issue using `Closes #<number>` or `Refs #<number>`. The issue is the design/specification record; the pull request is the implementation record. Releases are created from signed semantic version tags such as `v0.1.0` and include Android APK and Web/Wasm artifacts generated by GitHub Actions.

## Security

Do not commit secrets, signing keys, keystores, API tokens, ad identifiers, or store credentials. Automated checks include dependency review, secret scanning, static analysis, tests, and CodeQL where supported.
